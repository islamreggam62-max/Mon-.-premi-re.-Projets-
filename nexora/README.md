# NEXORA — Executive Business Operating System

Phase 1 of NEXORA: a dark, data-dense executive command center built with Next.js (App Router), TypeScript, Tailwind CSS and Lucide icons. It covers eight modules over a static, fictional demo dataset ("Meridian Holdings"). There is no backend, no API routes and no mock server.

## Quick start

```bash
cd nexora
npm install
npm run dev        # http://localhost:3000
```

| Script | What it does |
| --- | --- |
| `npm run dev` | Development server (Turbopack) |
| `npm run build` / `npm start` | Production build (every route is prerendered as static) / serve it |
| `npm run typecheck` | Generates route types, then `tsc --noEmit` |
| `npm run lint` | ESLint (Next.js core-web-vitals, TypeScript, jsx-a11y) |
| `npm test` | Vitest unit tests: dates, formatting, analytics, data integrity |
| `npm run check` | All of the above, in order |

Requires Node.js 22.12 or later (Vitest 5).

## Modules

| Route | Module | Highlights |
| --- | --- | --- |
| `/` | Command Center | Six KPIs with trends, executive briefing, alerts, initiative health (reported status next to signal-based risk), weekly throughput chart with table view, approvals awaiting you, highest workloads, milestones |
| `/team` | Team | Departments with average load; filterable, sortable directory with roles, availability and capacity meters |
| `/projects` | Projects | Portfolio cards with milestone timelines, progress vs. schedule, budget burn; cross-initiative milestone tracker |
| `/tasks` | Tasks | Kanban board and list view, search and filters (initiative, assignee, priority, overdue); blocked tasks show why |
| `/daily-reports` | Daily Reports | Compliance (on time / late / missing), today's blockers with who can clear them, structured check-in form, filterable feed |
| `/approvals` | Approvals | Budget, hiring and exception requests with SLA state and policy checks; approve, reject or request changes (a reason is required for the last two) |
| `/ai-intelligence` | AI Intelligence | Demo mode: rule-based executive briefing, risk radar with factor breakdown, published scoring method, evidence-backed signals |
| `/settings` | Settings | Workspace preferences, check-in policy, notification rules, RBAC matrix, security, integrations (all preview) |

## Architecture

```
src/
  types/            Domain interfaces (strict, readonly, discriminated unions)
  data/             Static demo records — the only place data lives
  lib/
    analytics/      Pure functions: risk, workload, compliance, insights, KPIs, briefing
    queries.ts      The single seam binding data to analytics; one view model per page
    dates.ts        Calendar arithmetic that never reads the runtime clock
    format.ts       Locale- and time-zone-explicit formatting (hydration-safe)
    labels.ts       Display vocabulary
    presentation.ts Status → tone + icon + label
  components/       UI (shell, ui primitives, one folder per module)
  app/              Routes, layout, metadata, theme tokens (globals.css)
```

Pages call `getXxxView()` from `lib/queries.ts` and pass plain, serializable view models to components. Phase 2 can replace `src/data/` with a real data source by changing `queries.ts` only.

### How the "AI" works in Phase 1

Nothing is generated by a model. The briefing, alerts and signals come from transparent rules in `src/lib/analytics/`, and the AI Intelligence page publishes the risk scoring method. Risk is the sum of capped factor points: schedule lag, budget burn ahead of progress, overdue and blocked tasks, blockers raised in check-ins, and missed milestones. Elevated starts at 30, high at 60. When the signals contradict the owner's reported status, the initiative is flagged. In the demo data this happens to Atlas ERP Migration.

### Demo-mode boundaries

- All data is fictional. E-mail addresses use the reserved `.example` domain.
- The reference date is fixed at **Friday 30 October 2026, 19:00 (Africa/Algiers)**, so every "overdue" and "this week" figure is reproducible.
- Approvals, check-ins and settings changes stay in the page's memory, are labelled "not saved", and disappear on reload.
- Pages are marked `noindex`: this is a private workspace application, not a marketing site.

## Design system

The tokens in `src/app/globals.css` use the brief's exact hex values (canvas `#070B14`, surface `#0F172A`, raised `#1E293B`, violet `#7C3AED` / `#8B5CF6`, borders `rgba(255,255,255,0.08)`). Status colors (emerald, amber, rose) were checked for contrast on the card surface. Every status pairs color with an icon and text. Charts follow one rule set: thin marks, an emphasis color for the current period, hover and keyboard tooltips, and a table view.

## Accessibility and responsiveness

- Skip link, landmark regions, one `h1` per page, `aria-current` navigation, labelled form controls with associated errors, and `role="meter"` for capacity and progress bars.
- A native `<dialog>` navigation drawer on phones and tablets: focus is contained, Escape closes it, and page scroll is locked.
- Verified at 390 px, 768 px and 1440 px with no page-level horizontal scroll. Wide tables scroll inside their cards or switch to card layouts.
- Respects `prefers-reduced-motion`.
